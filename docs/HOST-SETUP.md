# Build host setup (Linux)

Everything needed on the development machine to build the BSP. Reference
distribution: **Ubuntu 22.04 LTS** (Debian 11/12 and Fedora equivalents are
given at the end).

---

## 1. Resources

| Item | Minimum | Recommended |
|---|---|---|
| Disk space | 30 GB | 60 GB (Vivado excluded) |
| RAM | 8 GB | 16 GB |
| CPU | any x86_64 | 8 threads (`make -j` inside Buildroot) |
| Network | needed on the first build (downloads sources) | |

Vivado, if installed, needs another 60–100 GB on its own.

> Buildroot must **not** be run as root, and the path must not contain spaces.

---

## 2. Mandatory packages

```bash
sudo apt update
sudo apt install -y \
    build-essential gcc g++ make binutils patch \
    bc bison flex \
    gzip bzip2 xz-utils unzip cpio tar \
    perl python3 \
    rsync file wget git \
    libssl-dev libncurses-dev \
    device-tree-compiler \
    dosfstools mtools parted
```

What they are for:

| Package | Why |
|---|---|
| `build-essential`, `gcc`, `g++`, `make`, `binutils`, `patch` | build the host tools and the cross toolchain |
| `bc`, `bison`, `flex`, `libssl-dev` | required by the Linux kernel build |
| `libncurses-dev` | `menuconfig` |
| `gzip`, `bzip2`, `xz-utils`, `unzip`, `cpio`, `tar` | unpacking sources and building images |
| `perl`, `python3` | build scripts (kernel, U-Boot, Buildroot) |
| `rsync`, `file`, `wget`, `git` | source downloads and the `local` package method |
| `device-tree-compiler` | inspecting `.dtb` files (`dtc -I dtb -O dts ...`); U-Boot builds its own |
| `dosfstools`, `mtools`, `parted` | writing and inspecting the SD image |

Buildroot builds the rest itself as host packages: `host-genimage`,
`host-mtools`, `host-dosfstools`, `host-openssl`, `host-pkgconf`, `cmake`,
`meson`/`ninja`, and the whole cross toolchain. No `cmake` or `meson` from the
distribution is required.

### Check

```bash
gcc --version && make --version | head -1 && python3 --version && git --version
```

## 3. Optional

| Need | Package |
|---|---|
| Serial console to the board | `sudo apt install -y minicom picocom` (`picocom -b 115200 /dev/ttyUSB0`) |
| SD flashing with a GUI | balenaEtcher, or `usb-creator-gtk` |
| Flashing from the command line | already covered by `coreutils` (`dd`) |
| Inspecting the image | `sudo apt install -y kpartx` |
| Serial port access without `sudo` | `sudo usermod -aG dialout $USER` (log out and back in) |

## 4. Vivado (only to regenerate the bitstream)

Needed **only** for `./build.sh vivado synth`. Building the software from the
bitstream already in `board/ked/zu-nexus/boot/` needs nothing of this.

* **Vivado 2023.2**, with the Zynq UltraScale+ device family installed.
* Source the environment before building: `source /tools/Xilinx/Vivado/2023.2/settings64.sh`
* Ubuntu 22.04 is not an officially supported distribution for 2023.2 but works;
  the installer may ask for `libtinfo5`:
  `sudo apt install -y libtinfo5 libncurses5 libxrender1 libxtst6 libxi6`
* For JTAG cables install the drivers:
  `sudo /tools/Xilinx/Vivado/2023.2/data/xicom/cable_drivers/lin64/install_script/install_drivers/install_drivers`

`fsbl.elf` and `pmufw.elf` are regenerated by `./build.sh xsa <file.xsa>`, which
needs **XSCT/Vitis**. `BOOT.BIN`, on the other hand, is assembled with the
`bootgen` binary already included in the repository, so a normal rebuild does
not require Vitis.

| File | Where to get it | Destination |
|---|---|---|
| `*.dxnn` models | `sdk.deepx.ai` | `/home/ked/models` on the target |

is uncompressed (about 41 MB per second at 720p30).

## 6. First build

```bash
git clone <repo> ked-external
cd ked-external
./build.sh              # downloads Buildroot if needed, applies the defconfig, builds
```

The first build downloads several GB of sources and takes 1–3 hours depending on
the machine. Later builds are incremental.

Common failure on the first run:

| Message | Cause |
|---|---|
| `You must install 'xxx' on your build machine` | a package from §2 is missing |
| `Incorrect selection of kernel headers` | defconfig not re-applied: `./build.sh defconfig` |
| download errors | no network, or a proxy is in the way (`export http_proxy=...`) |

## 7. Other distributions

**Debian 11/12** — same list as §2; `libncurses-dev` may be `libncurses5-dev`.

**Fedora / RHEL**

```bash
sudo dnf install -y @development-tools \
    bc bison flex openssl-devel ncurses-devel \
    gzip bzip2 xz unzip cpio tar perl python3 \
    rsync file wget git dtc dosfstools mtools parted
```

**Arch**

```bash
sudo pacman -S --needed base-devel bc bison flex openssl ncurses \
    cpio unzip rsync file wget git dtc dosfstools mtools parted python
```

## 8. Quick verification

```bash
cd ked-external
./build.sh defconfig
grep -E "DXPOSE_QT|DX_STREAM|QT6BASE_NETWORK|TARGET_LOCALTIME" ../buildroot/output/.config
```

All of them should be enabled. From there, `./build.sh` produces
`../buildroot/output/images/sdcard.img`.
